# Spyglass-Pro — Bug & Security Audit (2026-10-02)

Scope: `run.py`, `spyglass_pro/app.py`, `spyglass_pro/runner.py`,
`spyglass_pro/static/js/app.js`, `spyglass_pro/templates/index.html`, and the
vendored engine packages under `spyglass_pro/modules/`.

Method: full read-through of every file, threat-model of the data flow
(browser → Flask → runner → vendored engines → subprocess/CLI), then targeted
runtime verification of each patch (HTTP smoke tests, token-gate matrix,
queue/timeout unit checks, live browser render).

---

## Critical / High — all patched

### 1. Flask debug mode ON by default (RCE)
`app.py` previously did `debug = os.environ.get("SPYGLASS_PRO_DEBUG", "1") == "1"`.
Werkzeug's debug console is an unauthenticated interactive Python shell —
arbitrary code execution on any reachable interface.
**Fix:** default flipped to `"0"`; opt-in via `SPYGLASS_PRO_DEBUG=1`
([app.py:154](spyglass_pro/app.py#L154)).

### 2. Server bound to all interfaces by default
Default host was `0.0.0.0`, exposing the unauthenticated dashboard (and its
scan engines) to the LAN/internet.
**Fix:** default `127.0.0.1`; `SPYGLASS_PRO_HOST` to change, with a startup
warning when a non-loopback bind has no token configured
([app.py:150](spyglass_pro/app.py#L150), [run.py](run.py)).

### 3. Known fallback SECRET_KEY
A hardcoded default key would allow session forgery the moment any route uses
Flask sessions.
**Fix:** `secrets.token_hex(32)` per process unless `SPYGLASS_PRO_SECRET` is set
([app.py:12](spyglass_pro/app.py#L12)).

### 4. No authentication on the API
Every endpoint (including scan triggers that run nmap/sherlock/browser jobs)
was open to anyone who could reach the port.
**Fix:** optional `SPYGLASS_PRO_TOKEN`; when set, all `/api/*` routes require
it via Bearer header, `X-Spyglass-Token` header, or `?token=` query
(constant-time compare). The HTML shell stays ungated so the JS can prompt for
the token. Frontend stores the token (URL token → localStorage) and retries
once with a prompt on 401
([app.py:38](spyglass_pro/app.py#L38), [app.js:6](spyglass_pro/static/js/app.js#L6)).

### 5. Unvalidated proxy URL written into the process environment
`/api/proxy` accepted any string and exported it to `SPYGLASS_PROXY`,
`ALL_PROXY`, `HTTP_PROXY`, `HTTPS_PROXY` — inherited by every subprocess.
`file://`, `gopher://`, control characters, etc. could poison engine behavior.
**Fix:** scheme whitelist (http/https/socks4/4a/5/5h), hostname required,
control chars and embedded whitespace rejected
([app.py:20](spyglass_pro/app.py#L20)). Verified: `file:///etc/passwd`,
NUL-bearing and space-bearing proxies all return HTTP 400.

### 6. Unbounded job queue, no per-job timeout (self-DoS)
`run_job` blocked on `future.result()` forever; a client could pile up heavy
scans (nmap runs up to 15 min) until the server stalled.
**Fix:** `MAX_QUEUE` (default 16, env `SPYGLASS_PRO_MAX_QUEUE`) rejects new
jobs when full; `JOB_TIMEOUT` (default 900 s, env `SPYGLASS_PRO_JOB_TIMEOUT`)
releases the requester — the scan itself keeps running, but the HTTP request
is answered promptly
([runner.py:62](spyglass_pro/runner.py#L62)). Verified: timeout fires at
0.51 s with a 0.5 s budget; queue-full returns a clean JSON error.

### 7. InstaCloak UI-hook race under concurrency
InstaCloak's progress hooks (`say`/`say_parts`/`section`) are patched
process-wide via `sys.modules` attributes — concurrent runs would interleave
progress lines and corrupt each other's reports.
**Fix:** `_INSTACLOAK_LOCK` serializes InstaCloak runs; spyglass/lens jobs
keep the pool's other workers
([runner.py:366](spyglass_pro/runner.py#L366)).

### 8. Raw exception leakage to the client
`{"error": "...failed: <full exception>"}` could carry multi-line tracebacks,
internal paths, and multi-kilobyte payloads.
**Fix:** `_safe_error()` flattens whitespace and caps at 300 chars; timeout
errors get a dedicated message
([runner.py:56](spyglass_pro/runner.py#L56)).

### 9. `javascript:`-URL XSS in the results table
`renderLinkTable()` built `<a href="escapeHtml(url)">` — HTML-escaping does
not stop a `javascript:` (or `data:`) URL from executing when clicked. Scan
results are third-party-controlled content.
**Fix:** `safeHref()` allows only `http:`/`https:`/`mailto:`; anything else
renders as inert text
([app.js:37](spyglass_pro/static/js/app.js#L37)). Verified live:
`javascript:alert(...)` and `data:text/html,...` → inert, real URLs clickable.

## Medium / Low — verified safe (no change needed)

- **Path traversal in artifact filenames** — `utils.safe_name()` strips every
  character outside `[A-Za-z0-9._+-]`, so `/`, `\`, and leading `..` cannot
  survive (`../../etc/passwd` → `etc_passwd`). Verified.
- **Shell injection** — no `shell=True` / `os.system` anywhere; all subprocess
  calls use argv lists.
- **Frontend rendering** — all dynamic content goes through `escapeHtml()`;
  only the link-href path (fixed above) was unguarded.

## Active scanning: removed

Spyglass-Pro is now **passive-only**. Active collection moved to a separate
project, so every probe was **deleted rather than disabled** — there is no
flag, environment variable or config path that re-enables any of it. This
section is the inventory, so the code is recoverable from git history for
the project that now owns it.

Only-reachable-from-removed-phases: `_dir_wordlist`, `_wordlist`, `_DIR_LIST`,
`_EXPOSURE_PATHS`, `_SECURITY_HEADERS`, `_TECH`, `_http_headers`,
`_analyze_headers`, `_analyze_cookies`, `_detect_technologies`,

Also the `_NMAP` / `_GOBUSTER` / `_HTPPX` tool constants in `utils.py`, the

`website.py` went from 1350 to 682 lines. `scanner.py` is deleted outright.

### Where the line sits

Ordinary DNS record lookups (A, AAAA, MX, NS, TXT, CNAME, SOA, SPF, DMARC)
are still performed, and DNSBL/reverse-DNS checks still run — those are how
passive host intelligence is gathered at all. A zone transfer is a deliberate
attempt to dump a whole zone and was treated as active, so it went too.

### What remains

Passive sources: DNS, crt.sh, CertSpotter, HackerTarget, Wayback CDX, WHOIS,
Shodan, InternetDB, RDAP, RIPEstat, DNSBL, ip-api, and the breach databases
behind email/username/phone. GreyNoise, Censys, AbuseIPDB, VirusTotal and NVD
enrichment are wired but need an API key; with none configured they return
nothing and the affected leg degrades. Social collection drives a browser
against the *platform*, never the target's infrastructure.

An earlier revision of this list credited AlienVault OTX as a source. No OTX
code exists anywhere in this tree — it was never implemented, and the four
subdomain sources that are implemented are crt.sh, CertSpotter,
HackerTarget and Wayback CDX.

## Merge provenance

The three engines under `spyglass_pro/modules/` are vendored copies, all
covered by this repository's single MIT license (see `NOTICE`). Their
original repositories were separate checkouts and have since been folded in
and removed; this section records where the vendored copies differ from the
upstream commits they were taken from, so the next sync is mechanical.

Vendored at: Spyglass-OSINT `357b451`, InstaCloak `9028d15`,
Lens-Extender `06d451a`.

### Ahead of upstream (fixes that exist only here)

- **`spyglass_osint/phone.py`** — defines `_ignorant()` and imports `json`.
  Upstream `357b451` calls `pool.submit(_ignorant, ...)` and `json.loads()`
  **without either one**, so upstream's `phone()` raises `NameError` on every
  run. Keep this copy; it is the fixed version.
- **`spyglass_osint/metadata.py`** — `_reconcile_file_type()` plus the
  `_FILE_TYPES` table, so ExifTool's catch-all `TXT/text/plain` no longer
  mislabels source files, markdown, yaml, json, logs, etc. Upstream has
  neither.
- **`spyglass_osint/username.py`** — drops `--only-found` from the
  user-scanner invocation. user-scanner 1.5.x made found-only the default
  and exits with a deprecation error if the flag is passed, so upstream's
  call fails before scanning anything.
- **`spyglass_osint/display.py`** — reduced to the `info`/`err` helpers the
  engine modules import. Upstream also carries the interactive CLI UI
  (banner, menus, per-module renderers); the dashboard replaced it.
- **`spyglass_osint/utils.py`** — `_verify()` accepts any `2xx`/`3xx` status
  instead of string-equality against `"200"` (upstream fix carried in), plus
  the `_extract_ips` helper upstream added later.

### Deliberate rewrites

- Imports are relative to the vendored package; `lens_extender` keeps its
  absolute `lens_extender.*` imports, which is why `runner.py` puts
  `spyglass_pro/modules/` on `sys.path`.
- Formatting follows this repo's `ruff` config (120 cols, isort ordering);
  upstream uses a narrower style. Line wrapping and import order differ; the
  logic does not.

### Cosmetic-only differences

- `lens_extender/config.py` (`get_proxy_url`) and `lens_extender/osint.py`
  (`_get_text`, the `_run_lookup` closure) exist upstream but are dead code —
  nothing calls them there either. The proxy reaches the dashboard through
  `SPYGLASS_PROXY` instead, applied by `runner.py`.
- `_SCHEMA_VERSION` is `1` in both copies.

## Operational notes

- Start with a token for any non-loopback deployment:
  `SPYGLASS_PRO_TOKEN=$(openssl rand -hex 24) python3 run.py`
- The dashboard is Flask's dev server — put a production WSGI server
  (gunicorn/uwsgi) in front for real deployments.
- `SPYGLASS_PRO_JOB_TIMEOUT` bounds request wait, not scan runtime; hung
  scans still consume a pool worker until they finish.

### Correctness and effectiveness pass (2026-10-04)

Four defects found reviewing what the tool actually *does* rather than how
it is written. None were security issues; all four reduced yield or
produced false findings.

**1. Passive sources were lost to a single failed request.** Every keyless
source (crt.sh, CertSpotter, HackerTarget, Wayback CDX, ip-api, RDAP,
RIPEstat) is a free endpoint that rate-limits and 5xxs under load, and each
was fetched exactly once — one 429 removed that source from the result with
no error anywhere, which is the worst way to lose data. `utils.retry_call`
now retries with capped exponential backoff, mirroring the behaviour
`lens_extender/osint.py::_get` already had, so both engines degrade alike.

Compounding it, `website._http_body` cached *empty* results, so one
transient failure poisoned that URL for the rest of the process. Failures
are no longer cached.

**2. The phone↔country correlation rule was matching unrelated countries.**
It compared an ISO alpha-2 code against a spelled-out WHOIS country with
substring containment: `"us" in "russia"`, `"ch" in "china"` and
`"in" in "indonesia"` each reported an unrelated number and domain as a
**match**, while a UK number against `"United Kingdom"` matched nothing.
Names are now compared normalized (accents, punctuation and case folded)
against canonical English names derived from `phonenumbers`, which is
already a dependency — so there is no hand-maintained country table to rot.
Aliases cover registrar spellings (`"Korea, Republic of"`, `"USA"`).
Single-word aliases compare by equality only, which is what stops `UK`
matching `UKRAINE`. Unresolvable input returns no match: a fabricated match
is worse than a missed one.

**3. A source was documented but never implemented.** `website.py`'s design
principles and the *What remains* list above both credited AlienVault OTX.
No OTX code exists anywhere in this tree. The four subdomain sources that
are implemented are crt.sh, CertSpotter, HackerTarget and Wayback CDX. The
keyed sources (Shodan, GreyNoise, Censys, AbuseIPDB, VirusTotal, NVD,
IntelX, HIBP) are wired but return nothing without a key, and are now
documented that way rather than listed as if they were live.

**4. A burner login could not succeed under the dashboard's own UI.**
`instacloak.auth` clears an Instagram challenge by polling a *visible*
browser window for 120 seconds. The dashboard's headless checkbox overrode
that, so ticking it with a burner enabled burned the full timeout and then
quietly continued logged-out — silently disabling the feature the operator
had just turned on. Headless is now forced off when a burner login is
enabled, and the override is reported as a note on the result rather than
applied invisibly.

Separately, the burner profile directory was the fixed path `login/`, so
rotating to a fresh burner inherited the previous account's cookies, device
fingerprint and any flag already attached to it. It is now keyed by the
burner username (`login-<username>`). The shared-per-burner profile across
targets is unchanged and still deliberate: one login, reused, rather than
re-authenticating for every target.

`tests/run_tests.py` — **289 checks, 0 failed** (was 269). The 20 added
checks cover the retry helper and its backoff, the un-cached failure path,
country matching in both directions, the burner/headless interaction, and
burner profile isolation. No network, no browser.
